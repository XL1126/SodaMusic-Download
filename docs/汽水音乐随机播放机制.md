# 汽水音乐随机播放机制

说明汽水音乐 PC 客户端「随机听歌 / 电台 / 歌单乱序」背后的接口与技术路径。  
基于 SodaMusic PC 3.5.1 / 3.7.0 逆向材料（IDL 契约、goapi path、sourcemap）整理，仅供本项目开发者学习研究。

---

## 一、结论先说

汽水音乐的「随机」**主要不是客户端对固定列表做本地洗牌**，而是：

1. **服务端信息流 / 推荐流**：根据已播历史、偏好模式、Feed 会话，持续下发下一批曲目。
2. **电台流**：以 `radio_id` 为上下文，用 `cursor` 翻页拉取下一首/下一批。
3. **歌单播放模式**：在歌单场景下由服务端按 `play_mode`（含强制乱序）返回播放队列。
4. **本地队列上下文**：客户端把当前场景写进 `queue_type` / `scene_name`，再通过 `track_v2` / `media-player` 拉真实播放地址。

因此：**随机结果由上游 API 决定**；客户端负责上报已播、选择偏好、切换模式，以及请求具体媒体 URL。

```text
用户点「随机播放 / 电台 / 继续听」
        |
        v
选择 Feed 接口（song-tab / radio/tracks / playlist/feed/media）
        |
        v
请求体携带 played_tracks / played_media / feed_mode / play_mode / radio_id
        |
        v
返回 items[] / media_resources[]（下一批可播内容）
        |
        v
客户端对单曲调用 track_v2（或 media-player）取播放资源
        |
        v
播放过程中上报 dislike / played，影响下一轮推荐
```

## 二、播放「随机」相关的常量

来源：`logs/asar-extract/idl-contracts/.._.._src_idl_goapi_contract_feed.ts`

| 常量 | 字面量 | 含义 |
|------|--------|------|
| PlayModeForcedShuffle | `forced_shuffle` | 强制乱序播放（服务端打乱歌单/队列） |
| PlayModePlayOnDemand | `play_on_demand` | 按需播放（点什么播什么） |
| PreferenceModeFamiliar | `familiar` | 偏好：熟悉向（更保守、更常听） |
| PreferenceModeFresh | `fresh` | 偏好：新鲜向（更探索） |
| FeedModeMix | `mix` | Feed 模式：混合内容 |
| FeedModeTrack | `track` | Feed 模式：以单曲为主 |
| FeedModeGuidanceColdStart | `cold_start` | 模式引导：冷启动 |
| FeedModeGuidanceDislike | `dislike` | 模式引导：不喜欢触发 |
| FeedModeGuidanceSkip | `skip` | 模式引导：切歌/跳过触发 |

`playlist.PlayMode` 在契约中为 string 类型，实际取值至少包含 `forced_shuffle`、`play_on_demand`。

## 三、核心 API

### 3.1 歌曲信息流（随机听歌主路径）

| Method | Path | IDL 方法 | 用途 |
|--------|------|----------|------|
| POST | `/luna/pc/feed/song-tab` | FeedSongTab | PC 歌曲 Tab / 随机听歌主入口 |
| POST | `/luna/feed/song-tab` | FeedSongTab | 通用路径（H5/移动端同源） |
| POST | `/luna/flow/recommend` | FlowRecommend | Flow 推荐流 |
| POST | `/luna/flow/recommend/not_pack` | FlowRecommendNotPack | 不打包的推荐流（请求结构同 FeedSongTab） |

**PC 实际调用**：优先 `/luna/pc/feed/song-tab`。

**请求体关键字段（FeedSongTabRequest）**：

| 字段 | 类型 | 作用 |
|------|------|------|
| `played_tracks` | TrackPlayed[] | 已播曲目，服务端做去重与口味更新 |
| `played_media` | MediaPlayed[] | 已播媒体（含视频等） |
| `selected_boost` | SelectedBoost | 用户主动加权（如选了艺人/风格） |
| `is_first_request` | boolean | 是否本会话首次拉流 |
| `feed_mode` | string | `track` / `mix` 等 |
| `preference_mode` | string | `familiar` / `fresh` |
| `total_request_count` | number | 累计请求次数 |
| `preference_mode_request_count` | number | 当前偏好模式下请求次数 |
| `is_did_first_request` | boolean | 设备维度是否首次请求 |
| `feed_preference` | FeedPreference | 更细的 Feed 偏好 |
| `interesting_search` | InterestingSearch | 兴趣搜索上下文（media + artist_ids） |
| `feed_type` | number | Feed 类型 |
| `feed_counts` | FeedCounts | 曝光/播放计数 |
| `did_first_use_time` | number | 设备首次使用时间 |
| `feed_extra` | FeedExtra | 扩展透传 |
| `count` | number | 期望返回条数 |
| `device_profile` | DeviceProfile | 设备画像 |
| `player_info_param` | FeedPlayerInfoParam | 播放器侧参数 |
| `full_media` | boolean | 是否返回完整媒体信息 |
| `limited_free_scene` | LimitedFreeScene | 限免场景 |

**响应（FeedResponse）**：

| 字段 | 说明 |
|------|------|
| `status_code` | 0 成功 |
| `has_more` | 是否还有下一批 |
| `items` | FeedItem[]，随机/推荐结果列表 |
| `predict_info` | 预测信息 |
| `extra` | FeedResponseExtra 扩展 |

**技术含义**：这是「随机听歌」的主数据源。客户端把已播与偏好回传，服务端给出下一批「看起来随机、实际可个性化」的曲目。

### 3.2 电台（Radio）随机流

| Method | Path | IDL 方法 | 用途 |
|--------|------|----------|------|
| POST | `/luna/pc/feed/radio/tracks` | FeedRadioTracks | PC 电台曲目流 |
| POST | `/luna/feed/radio/tracks` | FeedRadioTracks | 通用电台曲目流 |

**请求体（FeedRadioTracksRequest）**：

| 字段 | 类型 | 必填 | 作用 |
|------|------|------|------|
| `radio_id` | string | 是 | 电台 ID，决定内容池/主题 |
| `played_tracks` | TrackPlayed[] | 否 | 已播曲目，避免重复、影响下一首 |
| `played_media` | MediaPlayed[] | 否 | 已播媒体 |
| `flow_type` | number | 否 | 流类型（首刷/续播等） |
| `cursor` | string | 否 | 分页游标；首次可空，续播用 `next_cursor` |
| `trigger_info` | string | 否 | 触发上下文（入口场景） |
| `feed_radio_media_extra` | FeedRadioMediaExtra | 否 | 电台媒体扩展 |
| `passthrough` | string | 否 | 服务端透传字段，下一轮原样带回 |
| `limited_free_scene` | LimitedFreeScene | 否 | 限免场景 |
| `player_info_param` | FeedPlayerInfoParam | 否 | 播放器参数 |
| `full_media` | boolean | 否 | 是否要完整媒体对象 |

**响应（FeedRadioTracksResponse）**：

| 字段 | 说明 |
|------|------|
| `status_code` | 业务状态 |
| `has_more` | 是否可继续拉 |
| `next_cursor` | 下一页游标 |
| `items` | FeedItem[] 本批电台曲目 |
| `passthrough` | 透传字段，客户端下一轮带回 |

**技术含义**：电台是「按主题持续随机续播」。随机性体现在服务端根据 `radio_id + 已播 + cursor` 决定下一首，而不是客户端本地 `Math.random()`。

**典型续播流程**：

1. 用户进入某电台 → 得到 `radio_id`
2. POST `radio/tracks`，`radio_id` 必填，`cursor` 空，`played_tracks` 空或带上历史
3. 播放返回的 `items`
4. 快播完时再 POST，带上 `cursor=next_cursor` 与最近 `played_tracks`
5. 可选带回 `passthrough`

### 3.3 歌单内随机 / 按需播放

| Method | Path | IDL 方法 | 用途 |
|--------|------|----------|------|
| POST | `/luna/playlist/feed/media` | GetPlaylistFeedMedia | 按播放模式从歌单取下一批媒体 |
| POST | `/luna/playlist/related_media` | GetPlaylistRelatedMedia | 歌单相关媒体扩展 |
| GET/POST | `/luna/pc/playlist/detail` | GetPlaylistDetail | 歌单详情（顺序列表；乱序不在这里） |

**请求体（GetPlaylistFeedMediaRequest）**：

| 字段 | 类型 | 必填 | 作用 |
|------|------|------|------|
| `playlist_id` | string | 是 | 歌单 ID |
| `play_mode` | PlayMode | 是 | `forced_shuffle` 或 `play_on_demand` |
| `feed_session_id` | number | 否 | Feed 会话 ID，续播保持一致 |
| `played_media` | MediaPlayed[] | 否 | 本会话已播 |
| `click_media` | Media | 否 | 用户点击进入的那首 |
| `feed_extra` | RecExtraGetPlaylistFeedMedia | 否 | 扩展 |

**响应（GetPlaylistFeedMediaResponse）**：

| 字段 | 说明 |
|------|------|
| `has_more` | 是否还有 |
| `media_resources` | 下一批可播媒体 |
| `playlist_id` | 回显歌单 |
| `feed_session_id` / `next_feed_session_id` | 会话续接 |

**技术含义**：用户在歌单里点「随机播放」时，客户端应请求该接口并带 `play_mode=forced_shuffle`，而不是只在本地对 `playlist/detail` 返回的数组洗牌。  
`playlist/detail` 负责展示完整歌单；**乱序队列**走 `playlist/feed/media`。

---

### 3.4 相关推荐（从当前曲「随机扩散」）

| Method | Path | IDL 方法 | 用途 |
|--------|------|----------|------|
| GET/POST | `/luna/track/related` | GetRelatedTracks | 相关曲目 |
| POST | `/luna/media/related`、`/luna/pc/media/related` | GetRelatedMedia | 相关媒体 |
| POST | `/luna/flow/related/media` | FlowGetRelatedMedia | Flow 相关媒体 |
| POST | `/luna/media/assistant/related` | AiAssistantRelated | AI 相关推荐 |

**GetRelatedTracksRequest 关键字段**：`track_ids`、`artist_ids`、`scene_name`、`played_tracks`、`played_media`、`feed_related_media_extra`。

**GetRelatedMediaRequest 关键字段**：`media_list`、`artist_ids`、`scene_name`、`played_media`、`req_count`、`search_query`、`category_id`、`media_type` 等。

**技术含义**：播放器「相似歌曲 / 接着听」不是纯随机，而是以当前曲/歌手为种子的服务端推荐；客户端仍会回传 `played_*` 降低重复。

### 3.5 负反馈与模式引导（影响后续「随机」）

| Method | Path | 用途 |
|--------|------|------|
| POST | `/luna/dislike` | Feed 级不喜欢 |
| POST | `/luna/track/dislike` | 曲目级不喜欢 |
| POST | `/luna/feed/mode/guidance` | Feed 模式引导（冷启动/不喜欢/跳过） |
| GET/POST | `/luna/pc/feed/mode`、`/luna/feed/mode` | 获取/提交信息流模式配置 |

**FeedModeGuidanceRequest**：`scene`、`disliked_media[]`、`device_profile`、`feed_extra`。  
**响应**：`feed_mode_guidance`，客户端据此调整引导文案或默认模式。

## 四、从「随机列表」到「真正播放」

随机 Feed / 电台返回的是**媒体/曲目元数据**，真正播放资源仍走媒体接口。

### 4.1 单曲详情 + 播放资源（核心）

| Method | Path | 说明 |
|--------|------|------|
| POST | `/luna/pc/track_v2` | PC 主路径；Cookie + BDMS 签名 |

**GetTrackV2Request 关键字段**：

| 字段 | 说明 |
|------|------|
| `track_id` | 曲目 ID（来自 Feed items） |
| `media_type` | 媒体类型，通常 `track` |
| `queue_type` | **播放队列上下文**，标明当前来自哪种随机/列表场景 |
| `scene_name` | 场景名，如 `search`、`library` |
| `scene` | TrackV2Scene（契约类型） |
| `enable_refresh_api` | 是否允许刷新资源 |

**本项目已验证的默认值**（`server/apis/track-v2.js`）：

```json
{
  "media_type": "track",
  "queue_type": "search_one_track",
  "scene_name": "search"
}
```

客户端在随机 Feed / 电台场景下，`queue_type` / `scene_name` 会换成对应队列语义（例如歌单播放、电台续播），用于风控、统计与推荐闭环；具体枚举以客户端运行时为准。

**响应关键字段**：`track`、`track_player`（含 `video_model` 播放 URL）、`lyric?`、`expire_at`、`risk_result`。

### 4.2 通用媒体播放器

| Method | Path | 说明 |
|--------|------|------|
| GET/POST | `/luna/pc/media-player` | 按 media_id + queue_type 取播放信息 |

**GetMediaPlayer 请求关键字段**：`media_id`、`media_type`、`queue_type`、`vid?`、`enable_dash?`、`scene_name?`。

本项目视频下载默认：`scene_name=library`，`queue_type=favorite_track_playlist`（见 `server/apis/video-v2.js`）。

## 五、请求公共参数与鉴权

随机/Feed 类接口与其它 goapi 一样：

| 项 | 值 |
|----|-----|
| Host | `https://api.qishui.com` |
| Cookie | `sessionid=...`（登录后） |
| 公共 query | `aid=386088`、`app_name=luna_pc`、`device_platform=windows` 等 |
| Content-Type | `application/json; charset=utf-8` |
| 签名 | Feed 类通常 Cookie 即可；`track_v2` 等敏感媒体接口需要 BDMS（`X-Helios` / `X-Medusa` / `X-SS-STUB`） |
| 状态码 | `status_code=0` 成功；`1000016` 登录失效 |

## 六、和「本地洗牌」的对比

| 方式 | 汽水音乐实际做法 | 纯本地随机列表 |
|------|------------------|----------------|
| 队列来源 | 服务端 Feed / 电台 / playlist feed | 客户端持有完整数组 |
| 乱序算法 | 服务端决策（`forced_shuffle` 等） | Fisher-Yates 等本地算法 |
| 是否依赖已播上报 | 依赖 `played_tracks` / `played_media` | 不依赖 |
| 换一批 | 调接口 + cursor/session | 本地再洗一次 |
| 个性化 | 支持 familiar/fresh、boost、dislike | 一般无 |
| 离线 | 通常不可用（需上游） | 可用 |

对本项目的含义：

- 若要模拟官方「随机听歌」，应对接 `feed/song-tab` 或 `feed/radio/tracks`，而不是只拿歌单列表本地乱序。
- 下载链路与随机播放链路分离：随机接口给 **track_id 列表**，下载仍用 `track_v2` + 媒体 URL。
- 本项目当前代理覆盖登录、歌单、track_v2、下载等；**尚未封装 Feed/电台随机接口**，若要做「随机播放页」可按本文路径扩展 `server/apis/`。

## 七、推荐对接顺序（若在本项目扩展）

1. 登录拿到 `sessionid`（已有 `/api/auth/*`）。
2. POST `/luna/pc/feed/song-tab`（或先实现 `/api/feed/song-tab` 代理），body 带 `count`、`preference_mode`、`is_first_request=true`。
3. 从 `items[]` 解析出 `track_id` / `media_id`。
4. 对每首调用已有 `POST /api/track/v2`（内部走 `track_v2` + BDMS）取播放/下载资源。
5. 播放或跳过时，将 `played_tracks` 回传下一轮 Feed；不喜欢则调 `dislike`。
6. 电台场景：先从发现页/配置拿 `radio_id`，再 POST `radio/tracks` 用 `next_cursor` 续播。
7. 歌单乱序：`playlist_id + play_mode=forced_shuffle` 调 `/luna/playlist/feed/media`。
