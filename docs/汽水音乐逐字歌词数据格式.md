# 汽水音乐逐字歌词数据格式

说明汽水音乐（SodaMusic / Luna）歌词接口返回的 **结构化逐字时间戳数据**：字段含义、与标准 LRC/KRC 的区别、如何还原「进度字体」高亮，以及降级为标准 LRC 的规则。

样本来源：PC 客户端逆向材料、`track_v2` / `track` 的 `lyric` 字段、H5 分享页 SSR 中的 `audioWithLyricsOption`（示例曲《Never ending (Slowed)》- HFHW，`track_id=7613023084246386698`）。

---

## 一、结论摘要

| 问题 | 结论 |
|------|------|
| 是不是标准歌词文件（如 `.lrc`）？ | **不是**。是接口 JSON 里的结构化对象 |
| 有没有逐字时间？ | **有**。`words[]` 每个字/词带 `startMs` / `endMs` |
| 是否全球统一标准？ | **不是公开通用标准**；属字节系 Luna 接口约定，理念上接近 KRC/QRC/现代流媒体逐字歌词 |
| 能否导出标准 LRC？ | **能降级导出**（只保留句级时间），逐字时间会丢失 |
| 能否做进度字体？ | **能**。用 `words[].startMs/endMs` 按毫秒填充当前句 |

---

## 二、数据在哪里

### 2.1 曲目接口内嵌

| 接口 | 字段 | 说明 |
|------|------|------|
| `POST /luna/pc/track_v2` | `lyric` | 主路径；IDL `TrackIncludeLyrics = 'lyric'` |
| `POST /luna/pc/track` | `lyric` | 旧版；请求 `includes` 含 `lyric` |
| 无独立 `/luna/lyric` 文件下载接口 | — | 不下载 `.lrc` 文件 |

常见挂载路径（兼容）：

- `payload.lyric`
- `payload.lyric.content`（长字符串或嵌套结构）
- `payload.data.lyric`
- `payload.track.lyric`

### 2.2 分享页 SSR（H5）

分享页 `window._SSR_DATA` / 路由数据中可见：

```text
audioWithLyricsOption
├── track_id / trackName / artistName / duration
├── songMakerTeamSentences
└── lyrics
    └── sentences[]     ← 句数组（真正逐字源）
```

注意：`lyrics` **不是**直接数组，而是对象，句列表在 `lyrics.sentences`。

## 三、结构化字段定义

### 3.1 歌词块（Lyrics）

| 字段 | 类型 | 含义 |
|------|------|------|
| `sentences` | array | 歌词句列表（主数据） |
| （其它） | — | 可能还有翻译、音译等扩展，视版本而定 |

### 3.2 句（Sentence）

| 字段 | 类型 | 含义 |
|------|------|------|
| `text` | string | 整句文本 |
| `startMs` | number | 句开始（**毫秒**） |
| `endMs` | number | 句结束（毫秒） |
| `words` | array | 词/字级时间戳 |
| `type` | string | 行类型；实测可见 `"lrc"`（即便带 `words` 也可能是该标记） |

### 3.3 词/字（Word）

| 字段 | 类型 | 含义 |
|------|------|------|
| `text` | string | 单个字或词 |
| `startMs` | number | 开始（毫秒） |
| `endMs` | number | 结束（毫秒） |

### 3.4 周边字段（`audioWithLyricsOption` 顶层）

| 字段 | 含义 |
|------|------|
| `track_id` | 曲目 ID |
| `trackName` / `artistName` | 曲名 / 歌手 |
| `duration` | 时长（秒，浮点；示例 `137.077`） |
| `previewStart` / `previewEnd` | 试听区间 |
| `offsetStart` / `offsetDuration` | 偏移相关 |
| `songMakerTeamSentences` | 作词/作曲等署名句 |
| `coverURL` | 封面 |
| `encrypt` | 是否加密标记 |
| `hasCopyright` / `group_playable_level` 等 | 版权与可播级别 |

## 四、实例（Never ending (Slowed)）

### 4.1 整句 + 逐字

```json
{
  "text": "もしも夜が来ても",
  "startMs": 20,
  "endMs": 3940,
  "type": "lrc",
  "words": [
    { "text": "も", "startMs": 20, "endMs": 740 },
    { "text": "し", "startMs": 740, "endMs": 1260 },
    { "text": "も", "startMs": 1260, "endMs": 1780 },
    { "text": "夜", "startMs": 1780, "endMs": 2420 },
    { "text": "が", "startMs": 2420, "endMs": 2920 },
    { "text": "来", "startMs": 2920, "endMs": 3160 },
    { "text": "て", "startMs": 3160, "endMs": 3420 },
    { "text": "も", "startMs": 3420, "endMs": 3940 }
  ]
}
```

### 4.2 署名句（可能只有一个 word 覆盖整行）

```json
{
  "text": "作曲：HFHW",
  "startMs": 0,
  "endMs": 10,
  "words": [ { "text": "作曲：HFHW", "startMs": 0, "endMs": 10 } ]
}
```

## 五、和其它格式的关系

| 格式 | 载体 | 句时间 | 字/词时间 | 说明 |
|------|------|--------|-----------|------|
| 标准 LRC | `.lrc` 文本文件 | 有 `[mm:ss.xx]` | 一般无 | 事实上的交换格式 |
| 增强 LRC | 文本 | 有 | 部分实现有 | 非强制标准 |
| KRC（酷狗） | 二进制/文本 | 有 | 有 `<ms,dur,flag>字` | 私有格式 |
| QRC（QQ） | 文本 | 有 | 有 | 私有格式 |
| **汽水 JSON** | **接口字段** | **`startMs/endMs`** | **`words[]`** | **Luna 内部约定，非开放标准** |
| TTML | XML | 有 | 可有 | W3C 通用计时文本，偏专业制作 |

要点：

1. 汽水 **不下发独立歌词文件**，歌词是 JSON 元数据。  
2. 逐字能力与 KRC/QRC 同级，但 **字段名/层级是汽水（字节）自己的**。  
3. `type: "lrc"` 只是行类型标记，**不等于**标准 LRC 文件内容。

## 六、如何做「进度字体」高亮

播放时刻 `t`（毫秒）：

1. 找到当前句 `s`：`s.startMs <= t < s.endMs`（或最后一句已开始）  
2. 句内对每个 `word`：  
   - `t < word.startMs`：未亮  
   - `word.startMs <= t < word.endMs`：正在亮（可做局部填充）  
   - `t >= word.endMs`：已亮  

推荐 UI 做法（与官方观感接近）：

- 底层：整句暗色文字  
- 上层：同文字亮色裁切宽度 =「已唱进度」  
  - **有 `words`**：按字累计已结束时长 + 当前字的局部比例  
  - **无 `words`**：用句区间线性填充（近似）

伪代码：

```text
progressInLine =
  sum(endMs - startMs for words where endMs <= t)
  + clamp(t - currentWord.startMs, 0, currentWord.endMs - currentWord.startMs)
  / totalLineDuration
```

## 七、降级导出标准 LRC

```text
[mm:ss.xx]sentence.text
```

规则：

1. `sec = startMs / 1000`  
2. 时间标签用 `[mm:ss.xx]`  
3. `words[]` **不写入**标准 LRC（无法表达逐字）  
4. 可选头：曲名、歌手、作词/作曲（来自 `songMakerTeamSentences`）

示例输出：

```text
[00:00.00]Never ending (Slowed) - HFHW
[00:00.00]作曲：HFHW
[00:00.01]作词：HFHW
[00:00.02]もしも夜が来ても
[00:03.94]おもしろい
```

若需 **无损保留逐字**，应导出自有 JSON（保留 `sentences/words`），而不是 `.lrc`。

---

## 八、解析注意点

1. **单位**：`startMs/endMs` 是毫秒；不要当秒用（否则时间轴会错 1000 倍）。  
2. **层级**：`lyrics` 可能是 `{ sentences: [] }`，不要假设 `lyrics` 本身就是数组。  
3. **`type: "lrc"`** 与是否逐字无关，看有没有 `words`。  
4. **署名行**时间可能很短（0–10ms），只作展示。  
5. **翻译/音译**若存在，是并行句数组，不要和主歌词混成一行。  
6. **缓存**：按 `track_id + lyric uuid/update_time` 缓存，避免重复拉。

## 九、本项目相关实现（对照）

| 位置 | 用途 |
|------|------|
| `server/utils/recommend-utils.js` | `parseLrcToLines`：兼容 LRC / 毫秒戳 / KRC 行与 `<ms,dur,0>字` |
| `server/utils/lyric-fetch.js` | `track_v2` 无歌词时回退 `/luna/pc/track` |
| `server/utils/lyric-converter.js` | KRC 行 → 标准 LRC（导出/写标签） |
| `src/pages/RecommendPage.vue` | 句级 + 句内进度填充（当前尚未强制走 JSON `words[]` 逐字） |

若播放器要完全对齐官方逐字效果，应优先消费 `sentences[].words[]`，而不是只解析 LRC 字符串。

## 十、可导出的中间表示（建议）

用于内部播放器或二次导出：

```json
{
  "track_id": "7613023084246386698",
  "title": "Never ending (Slowed)",
  "artist": "HFHW",
  "unit": "ms",
  "sentences": [
    {
      "startMs": 20,
      "endMs": 3940,
      "text": "もしも夜が来ても",
      "words": [
        { "text": "も", "startMs": 20, "endMs": 740 },
        { "text": "し", "startMs": 740, "endMs": 1260 }
      ]
    }
  ]
}
```

标准 LRC 只是该结构的「句级投影」。
