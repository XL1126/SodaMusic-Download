# 安全、签名与公共机制

说明汽水音乐 PC 的 BDMS 签名、BDTicket 零信任、风控头、设备上下文与请求管线。详细逆向过程见 `docs/REVERSE-ENGINEERING-BDMS-SDK.md`。

---

## 一、请求管线（客户端）

```
业务代码 idlMethods
    → apiCaller 选择 /luna/pc/* 优先 path
    → 拼 TT 公共 query + fp
    → utils/request.ts sendHttpRequest
         ├─ 合并 Electron Session Cookies
         ├─ 计算 body MD5 → X-SS-STUB
         ├─ beforeSendHeaders 拦截
         │    ├─ 去掉 origin / referer
         │    ├─ qishui.com 且非 /passport/ /ttwid/ → 写 UA 并调 BDMS 签名
         │    └─ BDTicket 对白名单 path 追加签名头
         └─ TTNet(@luna/ttnet) HTTP/2 发送
    → 响应头：bdturing-verify / x-tt-verify-passport-decision / luna-abroad-type
    → status_code === 1000016 → 清空登录态
```

源码位置（extract）：

| 模块 | 路径 |
|------|------|
| 请求服务 | `src/services/request/request.ts` |
| 发送与拦截 | `src/utils/request.ts` |
| 启动与签名挂载 | `src/app.ts` |
| BDMS 封装 | `addons/bdms/index.js` → `bdms.node` |
| BDTicket | `src/libs/bdticket/*` + `bdticket.node` |
| 设备 | `device.node` |
| 网络 | `ttnet.node` |

## 二、BDMS 签名

### 2.1 模块

| 文件 | 角色 |
|------|------|
| `bdms.node` | N-API 模块，导出 `init` / `generateHttpSignatureHeaders` / `report` |
| `metasecml.dll` | 底层加密（混淆导出：`MSBridgeML`、`MSBridgeOV`、`o0o0`） |
| 依赖 | Windows + SodaMusic 安装目录；标准 Electron 无法直接加载 |

本项目路径默认：

```
%LocalAppData%\Programs\Soda Music\3.5.1\resources\app.asar.unpacked\bdms.node
```

可用环境变量 `SODAMUSIC_PATH` 覆盖。

### 2.2 调用方式

```text
1. process.env.PATH 前置 metasecml.dll 所在目录
2. bdms.init({ deviceId })
3. headers → "key\r\nvalue\r\nkey\r\nvalue"
4. result = bdms.generateHttpSignatureHeaders(url, headersStr)
5. result 按 \r\n 拆成 key/value 对写入请求头
```

生成的业务头：

| Header | 特征 |
|--------|------|
| `X-Helios` | 约 48 字符 base64；解码约 36 字节，含版本/标志类结构 |
| `X-Medusa` | 长 base64（样本约 872 字符）；高熵加密载荷 |

### 2.3 作用范围

| URL | 是否 BDMS |
|-----|-----------|
| `https://api.qishui.com/luna/...` 等业务路径 | 是 |
| `.../passport/...` | 否 |
| `.../ttwid/...` | 否 |

### 2.4 失败表现

| 接口 | 无签名结果 |
|------|------------|
| `/luna/pc/me` 等 | 仍可返回（仅 Cookie） |
| `/luna/pc/track_v2` | HTTP 200 + 空 body |
| `/luna/pc/video_v2` | 可能 status_code=1000062 |

签名与 URL/请求头绑定；更换 track_id 后旧签名不可复用。

### 2.5 本项目封装

`server/utils/bdms-signer.js`：

| 函数 | 作用 |
|------|------|
| `initSigner(deviceId)` | 加载 bdms.node 并 init（进程内一次） |
| `buildHeadersString(headers)` | 拼 `\r\n` 格式 |
| `generateSignatureHeaders(url, headers)` | 返回 `{ 'X-Helios', 'X-Medusa' }` |
| `parseSignatureResult(result)` | 解析签名结果串 |

当前 `deviceId` 固定为 `2117006317868281`，UA 为 `LunaPC/3.7.0(452316191)`。

### 2.6 X-SS-STUB

客户端在 body 读入 Buffer 后：

```text
X-SS-STUB = MD5(bodyBuffer).hex.toUpperCase()
```

若已有该头则不覆盖。属于 TTNet 发送前的请求体摘要，不是 BDMS 输出。

## 三、BDTicket 零信任

### 3.1 组件

| 文件 | 角色 |
|------|------|
| `bdticket.node` | 原生实现 |
| `@byted/bdticket-pc` | Node 封装：`init` / `refreshSettings` / `startBDTicket` / `handleRequest` / `handleResponse` |
| `src/libs/bdticket/config.ts` | 默认加签路径配置 |
| `src/libs/bdticket/index.ts` | 请求/响应钩子 |

初始化受设置开关 `bdticket_switch.enable_bdticket` 控制；`initBdticket()` 在 app ready 后执行。

### 3.2 默认加签路径（config_version 20250908.1）

`session_guard_config.ree_path`：

| Path |
|------|
| `/luna/pc/me/collection/media` |
| `/luna/pc/user/me/privacy/setting` |
| `/luna/pc/me/collection/playlist` |
| `/luna/pc/me/collection/album` |
| `/luna/pc/me/follow` |
| `/luna/pc/me/collection/artist` |
| `/webcast/room/create/` |
| `/web/api/media/user/info/` |
| `/passport/token/beat/web/` |

其它配置：

| 字段 | 值 | 含义 |
|------|-----|------|
| `enable` | true | PC 登录态加签开关 |
| `ree_enable_symmetric` | true | 启用对称加签 |
| `ree_path_prefix` | 空 | 前缀加签（测试可压测全量） |
| `ree_exclude_path` | 空 | 排除列表 |
| `enable_full_path_track` | true | 全链路埋点 |

### 3.3 签名输入

`handleRequest(host, pathname, headers, sessionID, sessionSS)`：

- Cookie 域 `.qishui.com` 中读取 `sessionid` 与 `sessionid_ss`。
- 返回附加头 + `associated` 上下文，响应回来时 `handleResponse` 继续处理。

本项目**未**实现 BDTicket；现有代理接口也未落在上述白名单上，故下载链路可工作。

## 四、风控与验证响应头

| 响应头 | 客户端处理 |
|--------|------------|
| `bdturing-verify` | 打开验证码窗口，成功后重放原请求 |
| `x-tt-verify-passport-decision` | 二次验证，失败抛「验证失败，请重试」 |
| `luna-abroad-type` | `0` 国内 / `1` 出境绿色通道 / `2` 海外；用于区分版权限制 |
| `x-tt-logid` | 请求日志 ID，排障用 |

本项目代理目前只透传 body；若上游返回风控头导致空数据，需在日志中关注 status 与 body 长度。

## 五、设备与公共参数

### 5.1 设备相关接口

| Method | Path | 用途 |
|--------|------|------|
| POST | `/luna/device/report/info` | 上报设备画像与应用列表 |
| GET | `/luna/device/recent-login` | 本机最近登录账号 |
| POST | `/luna/device/volume` | 音量策略 |
| GET | `/luna/launch/device` | 设备启动引导 |

设备指纹由 `device.node` 提供；`bdms.init({ deviceId })` 与请求 query 中的 `device_id`/`fp` 应保持一致。

### 5.2 平台限制

| 项 | 限制 |
|----|------|
| BDMS / metasecml | 仅 Windows |
| 本项目 server | `process.platform !== 'win32'` 直接退出 |
| 本机 Cookies 一键登录 | 仅 Windows |

## 六、常见业务错误对照

| 现象 | 可能原因 | 检查点 |
|------|----------|--------|
| track_v2 200 + 空 body | 缺 X-Helios/X-Medusa | bdms-signer 是否 init 成功 |
| video_v2 1000062 | 签名/权限 | 是否附加 BDMS；session 是否有效 |
| status_code=1000016 | 登录失效 | 重新扫码/一键登录 |
| status_code 非 0 且无资源 | 版权/会员/地区 | mcheck、commerce download 权限 |
| 响应 HTML | 会话过期或 WAF | Cookie；看 content-type |
| Cookies 读失败 EBUSY | 客户端占用 | 退出汽水音乐 |
